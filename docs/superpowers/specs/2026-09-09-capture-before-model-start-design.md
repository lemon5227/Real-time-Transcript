# 先录音后转录设计

日期：2026-09-09

## 背景

当前点击“开始听课”后，前端先等待 Socket.IO 的 `start_transcription` 回调；后端回调又要等本地 provider 完成 `start()`。在 Parakeet TDT v3 + MLX 首次加载模型时，这段等待可能持续数秒，因此麦克风尚未开始采集，开头音频会丢失。

Parakeet provider 已经使用连续流式接口 `transcribe_stream()`，并通过 `requires_contiguous_audio = True` 告诉后端不能使用 Whisper 式重叠窗口。模型完成启动后，可以持续接收音频并产生草稿和确认字幕；本次改动的目标是把“录音开始”和“模型就绪”解耦。

## 目标

- 用户点击开始后，获得麦克风权限即立即开始采集音频。
- 模型启动期间的音频不丢失，模型就绪后按序送入后端。
- 原声录音继续从会话开始保存，不依赖模型启动完成。
- 明确区分“正在收音、模型准备中”和“正在实时转录”两种状态。
- 保持现有历史字幕、临时字幕、翻译和自动跟随行为不变。

## 非目标

- 不更换 Parakeet TDT v3 + MLX 的模型或流式 API。
- 不重新设计课堂布局。
- 不让模型启动失败时无限堆积音频。
- 不把临时字幕写入课后历史记录。

## 方案

### 前端采集与待发送缓冲

点击开始后，前端按以下顺序执行：

1. 检查 Socket.IO 和麦克风能力，并完成麦克风权限请求。
2. 立即调用 `beginCapture()`，采集链路进入工作状态；音频回调不再要求 `state.recording` 已经为真，而是允许“正在启动”状态写入待发送队列。
3. 同时创建后端转录会话。拿到 `session_id` 后，将待发送队列中的 PCM 分片按 `sequence` 顺序发送，并继续发送后续实时分片。
4. 如果模型仍在启动，界面显示“正在收音 · 模型准备中”；收到 provider ready 事件后切换到“正在实时转录”。

待发送队列使用固定上限 30 秒，并按音频顺序维护。超出上限时丢弃最早的待转录分片，保留最新声音，向用户显示“模型准备较慢，已跳过少量待转录音频”。原声保存不受此队列上限影响。

### 后端会话生命周期

`SessionManager.start()` 创建会话状态和 worker 后立即返回会话元数据，不再同步等待 provider 启动。worker 仍在自己的线程中执行 provider `start()`，保证 MLX 的线程亲和性不被破坏。

事件分为两层：

- `transcription_session_created`：会话已建立，可以接收音频；包含 `session_id` 和请求的模型信息。
- `transcription_ready`：provider 已完成启动，可以开始推理；包含实际 provider 和模型信息。

如果 provider 启动失败，发送现有 `transcription_error`，并让前端保留录音能力，避免用户已经录下的原声丢失；前端停止继续向失败的转录会话发送待处理音频，并在结束课堂时仍保存本地原声和已有字幕。

### 停止行为

停止时先停止采集，再刷新前端尚未发送的 PCM 分片，最后发送 `stop_transcription`。后端 worker 会处理队列中已接收的音频、flush 音频窗口和 provider，返回确认字幕。若模型尚未 ready，停止流程仍应关闭 worker 并返回已确认结果，不阻塞原声保存。

## 状态与用户提示

前端增加独立的 capture/transcription 状态，不再用单一 `recording` 布尔值表达全部阶段：

- `idle`：未录音。
- `capturing`：麦克风已启动，模型尚未 ready；按钮显示结束听课，顶部提示正在收音。
- `recording`：麦克风和 provider 都 ready，正常实时转录。
- `stopping`：停止采集并等待最后结果。
- `error`：转录失败时仍允许结束并保存原声，给出切换模型或云端的操作建议。

顶部当前句和底部临时字幕只在收到后端 segment 时更新；模型未 ready 时不会伪造字幕，只展示真实的“收音中”状态。

## 错误处理

- 麦克风权限失败：不创建或清理转录会话，沿用现有重试麦克风提示。
- 模型启动慢：继续录音，最多缓存 30 秒待转录音频；不触发原有“启动超时即释放麦克风”的行为。
- 模型启动失败：显示可操作错误，停止向后端发送转录音频；用户仍可点击结束，保存原声和已有字幕。
- 后端连接中断：如果已有录音，继续本地保存；提示用户本次可结束并保存，禁止向不存在的会话无限发送。
- 后端队列满：沿用现有 `audio_backpressure`，但只统计已经进入后端的音频；前端待发送队列另行显示启动阶段的跳过提示。

## 测试

- SessionManager：验证 `start()` 在 provider 延迟启动时仍立即创建会话；启动完成后同一 worker 能按序消费预先进入队列的音频；启动失败会发出错误且 stop 可收尾。
- Socket 事件：验证 session-created 和 ready 事件顺序，以及启动期间 `audio_chunk` 不被拒绝。
- 前端契约：验证采集回调可在 `starting/capturing` 阶段入队；收到 session-created 后按序 flush；ready 前后 UI 文案不同；30 秒上限和结束时 flush 存在。
