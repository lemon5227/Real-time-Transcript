# MLX 实时转录基准

日期：2026-09-11

测试来源：[MLflow Full Course on YouTube](https://www.youtube.com/watch?v=_Ox2Ft0xumE)。
取前 59.99 秒音频，并下载英语自动字幕作为参考。音频和字幕只保存在本机的临时目录，
没有加入仓库。

## 启动与实时延迟

Apple Silicon + `Parakeet TDT v3 · Mac MLX`，服务配置为 `right_context=16`、基础流式块
`1.0s`：

| 指标 | 结果 |
| --- | ---: |
| 首次服务内启动到 ready | 0.96s |
| 同一服务第二次启动到 ready | 0.008s |
| 首个实时字幕 | 2.26s |
| 首个确认字幕 | 7.73s |
| 结束后补齐 | 0s |
| 最终段数 / 字幕事件 | 15 / 54 |

第二次启动的明显下降来自进程内模型缓存；每次会话仍然创建新的流式解码器，避免跨课堂
复用状态。

## 同一音频的流式与精细转录

参考字幕是 YouTube 自动生成字幕，不是人工校对的黄金标准。比较前先去掉词级高亮标记，
按滚动字幕的重叠词去重，再计算近似英文词级 WER；因此结果用于判断趋势，不作为模型
官方准确率声明。

| 模式 | 用时 | 实时倍率 | 词数 | 近似 WER | 近似词准确率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| MLX 流式，`right_context=16` | 21.94s | 0.366× | 120 | 0.423 | 57.7% |
| MLX 非流式精细转录 | 1.94s | 0.032× | 128 | 0.146 | 85.4% |

实时字幕已经能跟上音频，但会把 `MLOps`、`LLM`、`MLflow` 等术语拆错或在确认阶段
丢掉部分不稳定词；非流式精细转录同时更快、更完整。这验证了产品应明确区分：

- 上课时：低延迟流式字幕，允许少量不稳定词，优先让学生跟上老师。
- 课后复习：对保存的原声重新执行非流式精细转录，使用完整上下文修正术语、断句和时间轴。

因此后续复习页不应直接把实时确认字幕当作最终稿，而应提供“一键精细转录”，并保留实时稿
作为对照。
